Drusano–Greco Equation 2 DSL derivation

Purpose and scope

This note records how the two-drug Drusano–Greco equation in DrusanoModelFortran.docx maps to the predefined PMcore DSL model in drusano_greco.rs.

The current Checkmate fit treats the following as well-level covariates:

  • d1: drug 1 concentration divided by its assigned MIC;
  • d2: drug 2 concentration divided by its assigned MIC; and
  • effect: the normalized fractional drug effect, (E^*).

It estimates only these five parameters:

[ EC_{50,1},EC_{50,2},h_1,h_2,_{12}. ]

All other DSL quantities are deterministic substitutions. The current model is limited to two drugs and fits the algebraic interaction equation directly. It does not fit the bacterial-growth differential equation from the source document.

1. Starting equation

After normalizing the drug effect as (E^* = E/E_{con}), Equation (1b) in the source document is

[ 1 = {EC_{50,1}()^{1/h_1}} + {EC_{50,2}()^{1/h_2}} + {EC_{50,1}EC_{50,2} ()^{ (1/h_1+1/h_2)}}. ]

In Checkmate, effect is already (E^*), not the raw assay response. For an uncensored well it is calculated from the blank-adjusted growth response as

[ E^* = 1 - {_{}-}. ]

The scientific-core implementation of this normalization is in build_equation_dataset.

2. Substitutions

The source document introduces the following substitutions:

[ \[\begin{aligned} XM0 &= \frac{E^*}{1-E^*},\\ U &= \frac{D_1}{EC_{50,1}},\\ V &= \frac{D_2}{EC_{50,2}},\\ W &= \alpha_{12}UV,\\ H_1 &= \frac{1}{h_1},\\ H_2 &= \frac{1}{h_2},\\ H_{12} &= \frac{H_1+H_2}{2}. \end{aligned}\]

]

Their DSL equivalents are:

Source symbol DSL expression Role
(E^*) effect Covariate
(D_1) d1 Covariate
(D_2) d2 Covariate
(EC_{50,1}) ec50_1 Fitted parameter
(EC_{50,2}) ec50_2 Fitted parameter
(h_1) h1 Fitted parameter
(h_2) h2 Fitted parameter
(_{12}) alpha_12 Fitted parameter
(XM0) xm0 = effect / (1.0 - effect) Derived quantity
(U) u = d1 / ec50_1 Derived quantity
(V) v = d2 / ec50_2 Derived quantity
(W) w = alpha_12 * u * v Derived quantity
(H_1) h_1 = 1.0 / h1 Derived quantity
(H_2) h_2 = 1.0 / h2 Derived quantity
(H_{12}) h_12 = (h_1 + h_2) / 2.0 Derived quantity

The underscore is significant in the DSL naming convention: h1 and h2 are the fitted Hill parameters, while h_1 and h_2 are their reciprocals.

3. Equation 2 and the DSL output

Applying the substitutions produces Equation (2) from the source document:

[ 1 = + + . ]

Define the right-hand side as

[ S(E^*,D_1,D_2;) = + + , ]

where

[ = (EC_{50,1}, EC_{50,2}, h_1, h_2, _{12}). ]

A direct DSL transcription could therefore output (S) and use a constant observation of (+1). Checkmate instead outputs (-S):

out(neg_equation_rhs) = -(
    u / pow(xm0, h_1)
  + v / pow(xm0, h_2)
  + w / pow(xm0, h_12)
)

Each well is paired with the constant equation observation

OUT = -1

so the fitted equality is

[ -1 = -S. ]

Multiplying both sides by (-1) recovers Equation (2), (1=S). The leading minus sign is therefore an observation-model convention, not a change to the Drusano–Greco equation.

4. Equivalence to the source document’s squared error

For an uncensored well, let the observed value be (y=-1) and the DSL prediction be (f()=-S). The residual is

[ y-f() = -1-(-S) = S-1. ]

Therefore,

[ [y-f()]^2 = (S-1)^2 = (1-S)^2. ]

Using the source document’s definitions

[ T_1=, T_2=, T_3= ]

this is

[ (1-T_1-T_2-T_3)^2, ]

which is exactly the document’s Equation (3), BestM0. PMcore uses the configured statistical error model rather than literally running this single-well squared-error minimization, but the center of the uncensored observation model enforces the same algebraic equality.

5. Reason for negating the equation

The sign convention allows raw assay responses below the response limit of quantification to use PMcore’s CENS = 1/BLOQ likelihood in the correct direction.

A lower raw growth response corresponds to a larger normalized drug effect:

[ Y_{} < Y_{} E^*_{} > E^*_{}. ]

For a censored well, Checkmate supplies effect at the LOD boundary. Under the intended monotone effect relationship, evaluating Equation (2) at that lower boundary effect gives

[ S(E^*_{}) > 1. ]

After negation,

[ -S(E^*_{}) < -1. ]

PMcore’s BLOQ likelihood evaluates the probability of an output at or below the supplied observation limit. With OUT = -1 and out(neg_equation_rhs) = -S, the model inequality is oriented consistently with a below-limit raw response. If all observations were uncensored, the positive form (1=S) and negative form (-1=-S) would be equivalent and the minus sign would not otherwise be needed.

6. Difference from the original Nelder–Mead calculation

The source document describes using known doses and model parameters to solve Equation (2) for (XM0), then recovering effect as

[ E^* = . ]

That procedure treats (E^*) as the unknown and uses Nelder–Mead to minimize BestM0 for each requested dose combination.

The current Checkmate fitting problem is different:

  1. Each checkerboard well supplies observed d1, d2, and effect.
  2. xm0 is computed directly from the observed effect.
  3. PMcore NPAG estimates distributions for ec50_1, ec50_2, h1, h2, and alpha_12 across wells.
  4. Parameter values are favored when the calculated Equation (2) right-hand side is compatible with one, subject to the configured error and censoring models.

Consequently, the fit does not need a nested Nelder–Mead solution for effect. An implicit solution for (E^*) is needed later when fitted parameters are used to predict effects at new dose combinations, but not while fitting Equation 2 to checkerboard wells whose effects are already observed.
